# Research: Editor workspace shell

## R1. Realtime server: Hocuspocus 4 in the SvelteKit process
- **Decision**: `@hocuspocus/server` 4.x `Hocuspocus` class. A `ws` `WebSocketServer({ noServer: true })` handles `upgrade` events for path `/collab` on the same `http.Server`. Each connection calls `hocuspocus.handleConnection(ws, request)`, where `request` is a web `Request` built from the `IncomingMessage` (v4 requirement). Messages go to `clientConnection.handleMessage(data)` and close events to `handleClose(event)`. Dev: a Vite plugin `configureServer(server)` attaches to `server.httpServer`. Prod: `server.ts` creates `http.createServer(handler)` from `build/handler.js` and attaches the same function. Server modules use relative `.ts` imports only, never `$lib`/`$env` aliases, because Node runs them without Vite. Upgrades on other paths (Vite HMR) are left alone.
- **Rationale**: the constitution names Hocuspocus or y-websocket. `@y/websocket-server` 0.1.x depends on the yjs 14 prerelease, while `y-codemirror.next` needs yjs 13. Hocuspocus 4 peers on yjs ^13.6.8.
- **Alternatives**: y-websocket 1.x `bin/utils` (unmaintained path); Hocuspocus' own `Server` on a second port (two ports, no shared origin).

## R2. Persistence (updates + snapshots, constitution I)
- **Decision**: Hocuspocus hooks, no Database extension.
  - `onChange({ documentName, update })`: synchronously insert the update into `updates` (better-sqlite3 is sync, so the update is durable before the next message is processed).
  - `onStoreDocument` (debounce 500 ms, max 2000 ms, plus on last disconnect): in one transaction, upsert `documents.state = Y.encodeStateAsUpdate(doc)` and delete that document's `updates` rows with `id <=` the max id read at the start of the transaction.
  - `onLoadDocument`: apply `documents.state` (if any), then every remaining `updates` row in id order. If both are empty, seed the starter text into `Y.Text('content')` server-side (clients never seed, so it can't be duplicated). The seed's own update is persisted through `onChange` like any edit.
- **Rationale**: matches the constitution literally, and a crash loses no acknowledged edit (SC-001/SC-002 hold even across a crash). Compaction keeps the log short.
- **Alternatives**: `@hocuspocus/extension-database` snapshot-only (simpler, but loses up to 2 s on crash and doesn't store updates).

## R3. SQLite access
- **Decision**: `better-sqlite3` + `drizzle-orm`, migrations generated by `drizzle-kit generate` into `drizzle/` and applied with `migrate()` from `drizzle-orm/better-sqlite3/migrator` when the DB opens. WAL mode on.
- **Rationale**: constitution (Drizzle + SQLite). better-sqlite3 has prebuilt glibc binaries, so the Docker base is `bookworm-slim`, not alpine.

## R4. Editor
- **Decision**: `codemirror` meta-package (`basicSetup` gives line numbers, bracket matching, search panel, history keymap) minus `history()`, because `yUndoManagerKeymap` replaces it. LaTeX via `StreamLanguage.define(stex)` from `@codemirror/legacy-modes/mode/stex`. `yCollab(ytext, provider.awareness, { undoManager })`. Toolbar undo/redo call `undoManager.undo()/redo()`. Search button calls `openSearchPanel(view)`.
- **Rationale**: official packages. stex covers commands, braces, comments and math. `codemirror-lang-latex` is third-party and its extras (autocomplete) belong to feature 004.
- **Line wrapping**: `EditorView.lineWrapping` is on, as in Overleaf's editor; LaTeX paragraphs are long lines.
- **Note**: toolbar insertions use one `view.dispatch` each, so `Y.UndoManager` records them as one step (captureTimeout merges fast edits; call `undoManager.stopCapturing()` before the dispatch).

## R5. Panes
- **Decision**: `paneforge` (Svelte 5). Outer horizontal `PaneGroup` (sidebar | editor | pdf) and inner vertical group (file tree / outline), each with `autoSaveId` (local storage, FR-018). Sidebar and PDF panes are `collapsible` with `collapsedSize` 0. Arrow buttons on the handles call `pane.collapse()/expand()`. `minSize` per pane.
- **Rationale**: drag, collapse, keyboard-resizable handles (ARIA separator) and persistence come built in.

## R6. Outline
- **Decision**: pure `parseOutline(text)`. Scan lines, strip comments (unescaped `%` onward), match `\\(sub){0,2}section\*?(\[[^\]]*\])?\{`, then read the balanced-brace title and collapse inner commands to their text (`\emph{best}` → `best`). Re-run on doc changes, debounced 200 ms. Current-section highlight = last entry with line ≤ cursor line.
- **Rationale**: O(n) over 5,000 lines in well under a frame. A Lezer tree would need a real LaTeX grammar.

## R7. Connection indicator / offline
- **Decision**: `HocuspocusProvider` status events drive a "Saved / Connecting… / Offline" badge in the editor tab strip. The provider reconnects on its own and Yjs merges offline edits.
- **Test**: Playwright `context.setOffline(true)` may leave the open WebSocket up. The test closes the socket through a `window.__overtree.provider` handle exposed only when `import.meta.env.DEV` or `PUBLIC_TEST_HOOKS=1` (declared in `src/env.ts`, read from `$app/env/public`; SvelteKit 3 has no `$env/dynamic/public`).

## R8. Docker
- **Decision**: multi-stage `node:24-bookworm-slim`. Builder runs `pnpm install --frozen-lockfile && pnpm build`, and the runtime gets prod deps + `build/` + `server.ts` + `drizzle/` + `src/lib/server` (imported by server.ts). `CMD ["node", "server.ts"]`. Compose: `ports: ["${OVERTREE_BIND:-127.0.0.1}:${PORT:-3000}:3000"]`, volume `overtree-data:/data`, `DATA_DIR=/data`, `HOST=0.0.0.0` (the container must listen on all interfaces; the host-side binding stays loopback). `server.ts` defaults `HOST` to `127.0.0.1` for bare-metal runs.
